# 拾句 Android 部署实验

这里提供两种互不影响的手机使用方式。

## 方式一：直接安装 APK

Android 工程将现有 Python 服务、网页、六级/高中/考研/初中四本词书、例句和词组一起打进 APK。应用启动后只在手机内部的 `127.0.0.1` 启动服务，并由 WebView 打开，不需要电脑或网络。

单词、词组和例句朗读直接调用手机的系统 TTS，不把音频或学习内容发送到项目服务器。Manifest 已按 Android 11 及以上的包可见性规则显式声明 `android.intent.action.TTS_SERVICE`；程序会依次检测美式、英式和通用英语，并在无需网络的英语 voice 中优先选择系统标记质量最高的一个，再考虑地区和延迟。单词速度设为系统标准速度的约 60%，词组和例句约 70%，并使用适合清晰语音的音频属性。若系统英语语音尚未初始化，页面会短暂等待并显示具体状态，而不是直接退回 WebView 的语音接口。最终清晰度仍取决于手机安装的系统英语语音包。

进入单词记忆并聚焦答案框后，Android 会持续保持专用的移动专注视图：顶部只保留今日目标进度和“退出专注”，例句始终靠近屏幕上方；提交答案后会放大答案、词书释义、ECDICT 补充和整句中文，例句来源不在手机端展示；“回忆成功”和“回忆失败”保持为底部同一行的操作栏。进入下一题不会返回完整首页，而会继续显示顶部例句并自动请求打开输入法。

### 本地构建

1. 安装 Android Studio，并安装 Android SDK 35 与 JDK 17。
2. 用 Android Studio 打开本目录，等待首次 Gradle 同步完成。
3. 在 Windows 双击 `BUILD-DEBUG-APK.cmd`，或在终端运行 `./gradlew assembleDebug`。
4. APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。

将该 APK 复制到 Android 手机，允许“安装未知应用”后即可安装。APK 已包含 Python，手机不需要 Python、Termux 或其他运行环境。当前构建仅包含 `arm64-v8a`，适用于绝大多数现代 Android 7.0 及以上手机。

### 使用 GitHub Actions 构建

如果不希望在电脑安装 Android Studio，可以直接使用项目附带的 GitHub Actions：

1. 在 GitHub 新建一个仓库，将整个项目推送到仓库；根目录的 `.github/workflows/build-android-apk.yml` 会被自动识别。
2. 也可以只把 `android-package-experiment` 目录作为一个独立仓库上传；该目录内同样附带 `.github/workflows/build-android-apk.yml`。
3. 打开仓库的 **Actions** 页面，选择 **Build Android APK**，点击 **Run workflow**，再点击绿色的 **Run workflow**。
4. 按 `UPDATE-SIGNING.md` 配置固定签名密钥后运行工作流，等待任务完成，在页面底部下载 `shiju-android-release-运行编号`。
5. 解压下载的 ZIP，得到 `app-release.apk`。将它传到手机并允许“安装未知应用”即可安装；以后使用同一签名构建的新版本可以直接覆盖更新并保留数据。

首次构建通常需要几分钟下载 Gradle、Android SDK 组件和 Chaquopy Python 运行时。GitHub 下载区得到的是 artifact ZIP，必须先解压，不能把 ZIP 直接当 APK 安装。生成的是仅供安装测试的 debug APK，有效下载时间设置为 14 天。

如果旧 APK 打开后显示 Python 服务的 `404 Not Found` 页面，请使用 1.0.2 或更高版本重新构建。Android 可能用 `/data/user/0/...` 和 `/data/data/...` 两种路径表示同一应用目录；旧版将两者直接比较，会把真实存在的首页误判为越界文件并返回 404。1.0.2 会先规范化静态资源根目录，再执行路径安全检查。新版 WebView 也会直接打开 `/index.html`，服务端会将根路径和目录路径回退到首页，并在 APK 未包含首页资源时给出明确的启动错误。不同的 GitHub 临时构建机可能生成不同的 debug 签名；若手机提示无法覆盖安装，请先卸载旧测试版再安装新 APK。卸载会清除该测试版的本地账户和学习记录。

1.1.0 针对手机重新设计了学习页：顶部导航改为三行触控布局，学习进度压缩为摘要卡片，“每日目标与记录”默认折叠，答题卡可直接进入首屏。输入框聚焦后会进入键盘模式，暂时隐藏导航和统计，压缩例句间距，并让输入框与确认按钮保持在软键盘上方。Android Activity 同时使用 `adjustResize`，以便 WebView 高度随软键盘变化。

1.2.0 增加 Android 持久登录：一年有效的 HttpOnly 会话 cookie 与对应 token 都保存在应用私有目录，重新打开应用时默认恢复上次登录的账户；只有主动点击“退出”才会删除持久会话。启动图标也替换为与网页左上角一致的“拾”字标识。学习提示现会引导用户关注整句中每个单词的词性和含义，而不只记忆高亮目标词。

1.2.1 在“词书”下拉框增加“错题本 · 当前词书随机”。它会将当前六级或高中词书中的错词打乱后连续复习；记住的词会移出错题本，继续保留的词会追加到队尾再次出现。

1.3.0 增加永久历史错题。每个曾进入当前错题本的单词都会按用户和词书永久保留；选择“历史错题 · 第二轮随机”可以重新打乱全部历史错题。移除当前错题不会影响历史记录，在第二轮中再次标错会重新加入当前错题本。

1.4.0 内置 ECDICT 精简词典。目标词答案区同时显示原词书释义与词典音标、词性和补充释义；词书内其他词仍以虚线显示并可查看两套内容。词书外单词不显示标记，点击并确认后只查询词典含义，不提供例句、不改变学习记录。词典完全离线运行。

1.6.0 增加顶部“查词”：既可输入英文查中文，也可输入中文反查英文。输入“偷”会找到 `steal`，输入“小偷”会找到 `thief`，查询 `steel / steal / thief` 时会给出易混提示。主动查询不会加入错题本，也不会改变学习统计。四本词书的开放语料例句同时应用本地人工敏感内容审校，避免制度结论性褒贬、现实政治冲突、族群或宗教刻板印象等不适合初学者的内容。

1.6.1 保存每个错词最近一次被标错时的输入。在错题列表单词复习、错题本随机和历史错题第二轮中，答题区上方会显示这条记录；若当时直接输入 `2`，会明确注明当时表示不记得。记录按账户和词书保存在应用私有目录，覆盖安装后仍会保留。

1.6.2 将手机记忆页改为持续专注视图。聚焦答案框后，词书选择、统计卡和其他导航会持续隐藏；提交答案时保留放大的解析界面，进入下一题后例句仍位于顶部，并通过 Android 原生输入法接口重新请求打开软键盘。顶部新增紧凑的“今日已学 / 每日目标”进度条，以及用于返回完整首页的“退出专注”按钮。

1.6.3 修正专注模式的进入条件：只有用户亲自点击答案框才会首次进入，换词书、切换词组/例句和打开使用手册均不会触发；已经进入后，下一题仍会自动聚焦并打开键盘。答案页把整句翻译提前到词典补充之前，隐藏不必要的朗读栏以保证首屏可见，并增加专用“查词”入口。

1.6.4 修复长词典释义被底部决策按钮遮挡的问题。移动答案页现在分为固定语境区、中间独立滚动的解析区和底部占据真实布局空间的操作区；“我记住了”和“加入错题本”不再使用覆盖内容的固定定位，因此整句翻译、查词和 ECDICT 内容不会与按钮重叠。

1.6.5 在专注学习视图中恢复并固定显示紧凑朗读组件。输入键盘打开、尚未提交答案以及答案翻译已经展开时，均可直接朗读当前单词、当前词组/例句或停止播放；朗读栏参与正常布局，不覆盖中间解析区和底部决策按钮。

1.6.6 扩大专注学习视图顶部“退出专注”按钮的触控区域。按钮现在至少 48 像素高、带返回箭头和清晰边框，文字也由 10 像素增大到 13 像素，更容易单手点按；功能仍然是退出专注视图并返回完整首页。

1.7.0 增加跨设备 JSON 数据同步。顶部“数据同步”可通过 Android 系统文件选择器导出或导入备份；备份包含四本词书的进度、错题和温习次数，但不含密码，导入只合并、不清空本机数据。错题需完成第 3 次温习后才能移除。新用户默认使用高中词书和完整例句，已有用户保留原选择。

1.7.1 调整错题复习体验：历史输入只在提交答案后显示，避免干扰作答；专注模式新增“上一题（显示答案）”按钮，回退后直接展示答案解析页面。

1.8.0 重做每日错题温习：只有“回忆成功”才累计，同一错词每天最多一次；“回忆失败”和输入 `2` 不计数，失败词当轮最多再出现一次。完成后可额外随机温习一轮且不计数。错题列表会恢复进入单词前的位置；Android 系统返回键可退回对应列表或退出专注模式；上一题答案页新增“回到背诵”。

1.9.0 将跨设备备份升级为 JSON v2。错题和已学状态使用带版本的删除记录，手机已完成并移除的错题不会再被电脑旧记录恢复；温习按日期事件去重合并，两端不同日期的有效温习可以累加。导入时校验四本词书指纹，避免不同词书版本的 ID 错位。旧 v1 备份仍可导入，但会提示它无法传播旧删除操作。

### Android 数据

账户、学习状态、每日目标和错题本保存在 Android 应用私有目录。覆盖安装同一应用会保留数据；卸载应用通常会删除数据。APK 与 Windows 版不会自动联网同步，但可在“数据同步”中导出 JSON v2，再到另一端导入并合并。首次使用 v2 时建议先升级两端，再分别导出并交叉导入一次。

## 方式二：无需 APK，手机快速访问电脑

手机和电脑连接同一个可信 Wi-Fi：

- Windows 源码环境双击 `START-MOBILE-LAN.cmd`。
- Linux/macOS 运行 `./start-mobile-lan.sh`。

终端会显示类似 `http://192.168.1.20:8000` 的地址，在手机浏览器打开即可。所有账户和进度仍保存在电脑的 `data/users.json`。

局域网方式使用普通 HTTP，只适合家庭等可信网络，不应在公共 Wi-Fi 中运行。如果 Windows 防火墙询问是否允许访问，只勾选“专用网络”。

## 当前限制

- 当前环境没有 Android SDK，所以这里只完成并检查 Android 工程，尚未在本机实际产出 APK。
- 首次 Gradle 构建需要下载 Android Gradle Plugin 和 Chaquopy 的 Android Python 运行时；生成的 APK 在手机上可完全离线运行。
- debug APK 使用 Android 调试签名，适合个人安装测试。正式发布到应用商店前需配置自己的 release 签名。
